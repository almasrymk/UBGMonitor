# إجراءات صاحب المشروع

هذه الإجراءات لم ينفذها Codex. لا تسجيل أي سر أو مفتاح خاص هنا أو في المحادثة.

## R1-S08 — الاعتماد المكشوف والمستودع

- [ ] إلغاء اعتماد الترخيص المشترك الذي سبق نشره ومراجعة سجل استخدامه على المنصة. تأكيد الإلغاء بالتاريخ وclient identifier المناسب دون secret. إزالة القيمة من الكود لا تلغيها.
- [ ] تجهيز انتقال للتثبيتات الحالية قبل أي إلغاء قد يعطلها: اعتماد مستقل لكل جهاز بدل توزيع secret مشترك بديل. تسجيل الأجهزة الجديد مقفول افتراضيًا ولا يُعد منشورًا.
- [ ] إصدار البدائل على المنصة عبر الإدارة الآمنة، وتسليمها لكل تثبيت عبر مصدر إعدادات محمي؛ لا git ولا packages ولا chat.
- [ ] اتخاذ قرار بقاء المستودع public أو جعله private؛ كلا الخيارين لا يلغي إفشاء حدث سابقًا.
- [ ] تفعيل GitHub secret scanning وpush protection إذا كانا متاحين للمستودع/الخطة، ومراجعة alerts. إضافة CI وحدها لا تعادل تفعيلهما.
- [ ] دراسة تنظيف التاريخ اختياريًا مع تنسيق جميع clones/forks؛ ليس جزءًا من التنفيذ الحالي، ولا يعيد السر المكشوف إلى السرية ولا يغني عن الإلغاء.

## Run 1 — تحقق يدوي قبل إصدار

- [ ] تجربة نسخة جديدة على VM نظيفة: صفر monitor points، ولا Madkhal/Central warnings وهي غير مضبوطة.
- [ ] تجربة ترقية ببيانات عميل: نقاطه وكلمات المرور والترخيص والتقارير باقية، والعينات القديمة وحدها لا ترجع.
- [ ] مراجعة CI ثم تشغيل matrix الجديدة على Windows/Linux/macOS عند التصريح بالنشر؛ النسخة المحلية الحالية لا تثبت ذلك.

## Run 5 — قبل تفعيل التسجيل والإنتاج

- [ ] اعتماد دومين HTTPS ثابت وJWK عامة عبر قناة إدارية مستقلة، مع دعم مفاتيح التراخيص الحالية؛ لا تعتمد نسخة endpoint المستخرجة وحدها.
- [ ] اعتماد تصميم التسجيل اليدوي أو تحديد تجربة pairing المطلوبة.
- [ ] مراجعة migration additive وتجربتها على SQL Server staging بعد backup، دون تشغيل migrations عمياء على الإنتاج.
- [ ] إكمال حماية state/credentials والإدارة المحلية قبل provisioning دائم أو ربط بالواجهة.
- [ ] اختبار activation/heartbeat/deactivation/offline/upgrade على staging بين المشروعين.
- [ ] الموافقة على merge/deploy/enable في خطوة مستقلة؛ لا push أو نشر تلقائي في هذه الجولة.
